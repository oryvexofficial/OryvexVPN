# OryvexVPN source revision: status and release checklist

## What is included

- A newly rebuilt static GitHub Pages site (light/dark, interactive route finder, 404 page) with home, downloads, guide, privacy, mobile navigation, route information, and a Fox/Cloudflare relay section. It uses relative asset links and works as a project site under a GitHub Pages subpath. The route map and country picker are explicitly illustrations, not live status.
- A bundled, restricted Cloudflare Worker and its OryvexVPN status page, with “Created by Muvixo”. It requires a secret for health/proxy operations, validates HTTPS and allowed host suffixes, strips forwarding headers, constrains method/body sizes, sets a timeout, and returns redirects without following them.
- A Fox setup dialog: a Cloudflare token template, account selector, Worker upload, random secret, workers.dev enablement, automatic Fox setting, a retry if Fox configuration fails, and an optional Fox relay health check. Android opens Cloudflare’s token page in a system Custom Tab. Windows opens the system browser. OryvexVPN does not store the Cloudflare API token; Fox stores the relay URL/secret locally.
- Corrections to package asset keys, Android's narrow Fox API allowlist, the Windows tray icon path, Fox Windows resource metadata, mobile settings overflow, choice semantics, small-text contrast, and some reduced-motion behavior.
- Android network-security configuration denies external cleartext by default and allows loopback for the Fox local API. Android release builds require a private signing keystore on tagged releases; the previously included public fallback key was removed. Windows release workflow includes Authenticode signing for first-party executables and the installer, requiring a user-owned PFX on tagged builds.
- GitHub Actions references pinned to full verified commit IDs, cargo-ndk version pinned, Android tunnel source tag checked against its full commit, and stale desktop-lite build checks removed. The old destructive site generator was retired.
- MASQUE gateway verification now requires a matching bundled SPKI pin. The authenticated API and DNS-over-HTTPS paths invoke the embedded-root certificate/SAN verification before sending HTTP requests. This is an uncompiled source change and needs platform tests. Pin rotation can block connectivity until pins are updated.

## Checks run in this sandbox

- Python unit suite, static site/link/asset checks, Cloudflare Worker Node tests, Fox WebChannel Node fixture tests, shell syntax, Android XML parsing, source security assertions and C bypass `make test`.
- No Rust/Cargo, Go, Flutter, Gradle, Android SDK, Windows SDK, was available in the sandbox. A browser preview was attempted, but its frame was blocked by the preview security policy. Thus no Flutter analysis, native builds, platform UI tests, Android installation, Rust/Go tests, actual Authenticode signing, or visual browser verification was performed. These are required before release.

## Important unresolved items

1. **No live deployment or publication occurred.** A Cloudflare account with Workers enabled, a scoped token, access to the target GitHub repository/Pages, and appropriate permissions are required. Cloudflare API operations and health in a real account have not been exercised.
2. **In-app Cloudflare OAuth is not fully automatic.** Cloudflare's token page runs in Android Custom Tabs and the system browser on Windows. The user must sign in, create and paste a token. True OAuth requires a registered Cloudflare public OAuth client, approved redirect URIs and a client ID; no such registration is supplied. No Cloudflare password is collected by OryvexVPN.
3. **The Firefox sign-in browser page does not traverse this HTTP Worker.** Fox backend API requests may use it; this does not guarantee bypass when the login webpage or workers.dev itself is blocked. It is not a general VPN and success in Iran depends on the network and service.
4. **Release signing requires owner-controlled credentials.** Configure all four `ANDROID_KEYSTORE_*`/alias/password secrets and `WINDOWS_PFX_BASE64`/`WINDOWS_PFX_PASSWORD` before tagged builds. The old Android fallback key was public and must be treated as compromised. Re-signing with a different key generally cannot update an existing installation in place; plan export/reinstall or an appropriate platform-supported migration. No production certificate or signing secret is included.
5. **Security-sensitive unverified code.** Compile and exercise the TLS changes on Android and Windows, including trusted, forged, wrong-host and IP-address SAN cases, and verify live MASQUE pins. The verifier now checks both the HTTP authority and any different SNI, including DNS and IP SANs, but server-auth purpose/EKU enforcement and live certificate behavior still need review and executable tests. Do not interpret static checks as proof of endpoint authentication.
6. **Privileged Fox TUN service maintenance remains unresolved.** Admitted users can request service update/uninstall; it needs a separate administrator authorization boundary on Unix and Windows and platform tests. The unauthenticated handshake has a deadline and connection cap, but that does not resolve authorization. The shipped Windows Fox app is documented as SOCKS-only, not whole-device TUN.
7. **Brand and release compatibility.** OryvexVPN is the visible app/site brand; Muvixo credit is retained as requested. Legacy Arman names remain in upstream Go module paths, migration code, service identifiers, and dormant legacy updater paths to preserve compatibility and legal provenance. Those paths still need a tested migration before being shipped as an Oryvex updater. Do not mass-rename them without migration tests.
8. **Supply chain and site checks.** Actions are commit-pinned, but some toolchain versions and an actionlint download remain mutable; the Lyrebird Go module-proxy fallback still lacks a separately recorded checksum. Site links and assets pass static checks, but responsive layouts, keyboard interaction, and color rendering were not tested in a real browser. Absolute canonical/OG image URLs remain unset because the final Pages/custom domain was not supplied.
9. **Run a real release gate.** At minimum run `flutter analyze && flutter test` for all Flutter packages, `cargo fmt --check && cargo test --lib` in `oryvexcore`, `go test ./...` in `fox/core`, Android Gradle/unit/device tests on API 24 and current Android, Windows installer/signature tests, and browser checks at mobile/desktop sizes. Review reports before distributing.

## Revision note (site rebuild)

- `site/` was rebuilt from scratch: new layout, type, colour, motion (reduced-motion respected), route finder, relay section with an in-app dialog illustration. Local link/asset/Worker/WebChannel checks pass; **it has not been viewed in a real browser** (the sandbox preview could not open local pages), so check mobile and desktop widths, keyboard use before publishing.
- Visible "Arman VPN" text in the Linux installer script and TUN service description now reads OryvexVPN. Internal identifiers (Go module path, binary names such as arman-vpn-*, Windows service/registry/folder names, updater asset names) are deliberately unchanged: renaming them breaks upgrades and data migration and needs a compiled, tested migration.
- Items 1 to 9 above are unchanged: they need real toolchains, accounts and signing keys.
